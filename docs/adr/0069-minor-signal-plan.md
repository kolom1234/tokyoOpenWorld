# ADR-0069: 간선 × 작은 길 교차로 minor 신호 계획(100 s)·계획별 연동 — 메이지도리 속도 비율
- Status: Accepted (M07 사전 ①-2)
- Date: 2026-10-05

## Context
M06-T05 수락 ⚠️: world-mini 10분(40대) 메이지도리(제한 50 km/h 차선) 평균 속도 비율 0.36–0.37, 목표 0.4–0.8(ADR-0065). 원인 분석(같은 하네스, 차선별 시간 분해):

| 변형 | 비율 | 순항 / 저속 / 적신호 대기 / 대기열(s) |
|---|---|---|
| 현재(120 s 주기) | 0.36 | 977 / 3,933 / 1,239 / 1,300 |
| 신호 모두 녹색 | 0.82 | 3,151 / 3,076 / 0 / 13 |
| 연동 오프셋 끔 | 0.36 | 966 / 3,873 / 1,334 / 1,356 |
| 메이지도리를 모든 교차로 주축 A로 | 0.46 | — |
| 주축 녹 77 s / B 33 s(120 s) | 0.35 | — |
| 주기 100 s(57/33) 전 교차로 | 0.41 | — |
| IDM a 1.6–2.0·T 1.2 | 0.36–0.37 | — |

- 손실은 신호(0.82 → 0.36): 적신호 대기 + 대기열 방출. 512 m에 신호 4개(150–250 m 간격), 트립당 1–2개라 한 방향 녹색 물결은 효과 없음(오프셋 끔과 같음).
- "저속"이 큰 것은 원하는 속력 분포(제한 × 0.85–1.10)와 가속 구간 — 신호가 없어도 절반. IDM 가속·간격을 키워도 거의 변하지 않음.
- 주축 녹색 비율만 늘리면 오히려 0.35(메이지도리가 B인 교차로가 있음 — 246 교차, 그쪽 대기 증가). 주기를 줄이면 평균 대기(R²/2C)가 줄어 0.40–0.43.

## Decision
1. `content/sim/signal-plans.json` 계획 추가(번호 추가만): **`minor`**(2번) 주기 100 s = A 녹 57 + 점멸 5 · 황 3 · 전적 2 · B 녹 23 + 점멸 5 · 황 3 · 전적 2. 계획에 `coordinated` 플래그(기본·minor = true, 스크램블 = false).
2. 파이프라인 `siteFinder(…, rules)`: 사이트(스크램블) 밖 교차로에서 주축 ±15° OSM 차도 최대 등급 가중 ≥ 3(secondary 이상)이고 다른 축 ≤ 2(tertiary 이하)면 `minor`.
   `SignalSite.cycleS·coordinated` → 연동 칸 = 주축 위치 ÷ 12 m/s를 **그 계획 주기로** 접음(minor 100 s). 소품 신호기·차선(lanes.bin)·내비 횡단이 같은 함수.
3. sim `CompiledPlan.coordinated`(없으면 0번만 — 옛 파일 호환) → 오프셋은 연동 계획에만.

## Consequences
- world-mini 메이지도리 신호 4개 중 3개 minor → 비율 **0.41**(교착·적신호 통과 0) — 수락 테스트 하한 0.3 → 0.4.
- 실제 도쿄의 생활도로 교차 신호(짧은 주기)와 맞는 방향. 간선 × 간선(메이지도리 × 246 등)은 120 s 그대로.
- 신호 코드 계획 비트가 바뀌므로 MVP 재빌드 필요(props.inst·lanes.bin·nav.bin). 옛 빌드 + 새 코드 = 계획 2번 없음 → 0번처럼 동작(호환).
- 대안(미채택): 양방향 연동(maxband) — 교차로 간격·주기에 맞춘 0/반주기 오프셋, 노선 단위 최적화가 필요해 MVP 밖.

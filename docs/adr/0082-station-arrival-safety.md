# ADR-0082: 역 계단 도착 = 승강장 윗면 메시 + 가장자리 여유, 선로 구덩이 구조, 출구 4역, validate stations
- Status: Accepted (M07-T06 후속 — staging 사람 확인)
- Date: 2026-10-13

## Context
staging 확인: 하라주쿠에서 계단 F로 승강장에 가면 "고가 선로 아래 도로"로 떨어져 열차가 머리 위에 있고 탈 수 없었다.
실제 GPU 재현(봇): F 도착 자체는 승강장 윗면(30.44 m)이었지만 도착점이 승강장 6(2020 섬식) **서쪽 가장자리에서 1.2 m**였고, 그 가장자리 선로(외회)는
파이프라인이 "선로에 가장 붙은 승강장"으로 **옛 외회 승강장 1**에 정차시켜 승강장 6 서쪽엔 홈도어가 없었다. 오른쪽(서)으로 한 걸음이면 레일(29.3 m — 충돌 없음) 아래
지형(27.9 m) 구덩이로 떨어지고, 물리에는 승강장 윗면만 있어 구덩이에서 승강장 **밑**(틈 2.6 m)으로 걸어 들어갈 수 있었다 = 스크린샷(양쪽 열차 바닥이 머리 위, 승강장 밑면이 천장).
또 도착 높이를 물리 레이 첫 면으로 정해 철도 정적 묶음이 없으면(적재 전·워커 재시작) 아래 지면에 놓일 수 있었다. 출구는 하라주쿠 1곳뿐이었다.

## Decision
1. **정차 승강장 우선**(`content/sim/rail-lines.json stations[].preferPlatforms`, 파이프라인 `trackStops(…, prefer)`): 하라주쿠 = `a288861390`(섬식 — 내·외회 공용). 옛 승강장은 정차가 없어 빌드에서 빠진다.
2. **도착 = 승강장 윗면 메시**(apps/game `station/platform-geo.ts` — sim `railStatic().platforms` 윗면 삼각형 8 m 격자): 높이 = 윗면, 반경 1.2 m 원(12방위 × 2) 모두 윗면인 점만
   (`safeArrival` — 힌트가 맞으면 그대로, 아니면 8 m 안 가까운 순). 철도 적재 전이면 "승강장 준비 중…"으로 이동하지 않는다. 올라가기(거리)는 물리 레이 + 내용 파일 높이 대체.
3. **구덩이 구조**(`trackPits`): walk 중 발이 승강장 8 m 안 선로 회랑(±2.6 m) 레일 아래 0.25–2.8 m이거나 승강장 윗면 아래 0.6–4 m면 0.4 s 뒤 페이드 → 가까운 승강장 윗면 + 알림.
   고가 아래 거리(레일 4 m+ 아래)·승강장에서 먼 선로는 제외. 물리 승강장 묶음에 **옆면**도 넣어 구덩이에서 승강장 밑으로 못 들어간다. 격자는 윗면·구덩이를 다른 프레임에, 구덩이는 프레임당 12k 표본(호출 ≤ 4 ms).
4. **출구 4역**(`content/stations/access.json`): 하라주쿠 다케시타·요요기 서쪽·신주쿠 서쪽·시부야 하치코 — 개찰구·계단 표식은 실제 GPU 물리 레이로 확인한 평탄한 거리 바닥, 승강장 표식은 탑승 승강장 중심선(가상 배치).
5. **자동 검사**: `pnpm pipeline validate`의 `stations`(빌드 rail.bin ↔ access.json — 탑승 정차역마다 출구, 도착점이 탑승 정차 OSM 고리 안·가장자리 ≥ 1.2 m, 표식 높이 ±0.3 m, 표식 고리 안)와
   실제 GPU `pnpm stations`(`tests/golden/stations.spec.ts` — 모든 출구: 계단 F → 발 = 윗면 ±0.2 m·여유 ≥ 1 m → W 2 s 뒤 윗면·구덩이 아님 → 승강장 F → 거리 ±1 m).

## Consequences
- 계단 이동은 여전히 페이드(계단·콘코스 기하 ⚠️ 후속). 승강장 끝(홈도어 밖)·탑승 노선이 없는 쪽 가장자리(요요기·신주쿠 주오선 쪽)는 열려 있고 구조가 받는다.
- 구조 판정 수치(8 m·0.25–2.8 m)는 MVP 4역 실측 기준 — 역을 늘리면 `pnpm stations`로 다시 확인.
- 하라주쿠 승강장 높이 맞춤(ADR-0081)이 두 선로 평균으로 바뀐다(외회 레일 ≈ +0.05 m).

# ADR-0052: 나무·식생 = OSM·규칙 배치 + trees.inst + ez-tree 수종 6종(파이프라인 생성) + CPU 굽기 반팔면체 임포스터 + 셰이더 인스턴싱 (M05-T04)
- Status: Accepted (⚠️ 빽빽한 숲 GPU — 아래)
- Date: 2026-10-01

## Context
M05-T04: ez-tree로 은행·느티·벚·녹나무·소나무 + 관목, 옥타헤드럴 임포스터, PLATEAU veg/OSM 위치, 바람, 계절 틴트. 수락 = 오모테산도 느티나무길 골든뷰, 나무 GPU ≤ 2 ms.
MVP 원천: PLATEAU veg(식생)는 정규화 대상이 아니다. OSM 간토에 나무 점 1,635·가로수열 108·숲 292·공원 211·잔디 182·관목 102·정원 71 면. 지형 `_SURF`는 공원까지 광장(7)이었다(PROGRESS Known Issue).

## Decision
1. **지면**: OSM 녹지 면(공원·정원·잔디·관목·숲)을 지형 `_SURF` 잔디(2)로 덧칠(도로·보도가 아닌 plaza 샘플만, `derive/vegetation.ts`). 숲 바닥 흙(3)은 수관 틈으로 붉은 흙이 드러나 잔디로 통일.
2. **배치**(`derive/trees/*`, 셀 예산 4k — 넘치면 채우기부터 버림): OSM 나무 점(차도 위면 3 m 안 보도로, 못 찾아도 차도 중심선 3.5 m 밖이면 그대로 — PLATEAU LOD1 도로는 보도 포함 전체 폭이라
   오모테산도 37그루 중 36이 버려졌다)·가로수열 8 m → 규칙 가로수(trunk·primary·secondary·tertiary 양쪽 보도 폭 ≥ 2.5 m, 차도 끝 + 1 m, 10 m, 교차부·횡단·OSM 나무·소품 근처 생략)
   → 녹지 격자 채우기(월드 정렬 격자 — 숲 6.5 m·90 %, 공원 12 m·40 %(잔디밭 ½), 정원 9 m·40 %, 관목 3.5 m·50 %). 수종 = 태그(genus·species·name) → 도로 이름 표(`表参道` = 느티) → 도로마다 해시 가중
   (은행 .45·느티 .25·벚 .2·녹나무 .1) / 숲(녹나무 위주)·공원 혼합. 결정론: 격자·선 정거장은 전역 번호 시드(셀 무관). 줄기 콜라이더 = 원기둥(높이 × 0.02, ≤ 3 m), 관목 = 덤불 원기둥.
3. **trees.inst**(05 §4 그대로 24 B 레코드) + `TREE_SPECIES`(1 은행 … 6 관목). 헤더 instances = 소품 + 나무.
4. **수종 에셋**(`pnpm pipeline trees`, 호스트 Node 14 s): ez-tree 1.1.0(MIT) 프리셋 + 덮어쓰기(가지 단면·마디를 줄여 LOD0 3.4–8.4k 삼각형), 높이 1 정규화, LOD1 = 가지 meshopt 15 % + 잎 카드 ¼ × 2배.
   잎 모양은 **자체 절차 아틀라스**(512², 활엽·은행 부채꼴·벚·솔잎 — ez-tree 텍스처 미사용), 임포스터는 **CPU 래스터 굽기**(반팔면체 8 × 8 × 64 px, 수종 6 → 1536 × 1024, 색 = 명암·잎 여부·덮임).
   산출 `apps/game/src/assets/trees/`(GLB 0.83 MB + PNG 0.73 MB) — 05 §1 `shared/trees/`(월드 빌드) 대신 게임 해시 에셋(아바타와 같은 방식, 첫 표시 뒤 지연 적재, 골든 대기 조건).
5. **렌더 인스턴싱 = Mesh + InstancedBufferGeometry**(InstancedMesh 아님): 속성 `_ipos`(렌더 좌표·yaw)·`_iext`(높이·씨앗·수종)로 셰이더가 직접 변환 → RenderObject 캐시 키에 객체 uuid가 안 들어가
   수종 × LOD 풀 24개 + 임포스터 1개가 노드 빌드 3번(수피·잎·임포스터)을 공유(ADR-0051의 InstancedMesh 140 ms/개 문제 회피). 64 m 블록 거리 LOD: 상세 ≤ 30 m, 간략 ≤ 60 m, 임포스터 ≤ 2 km
   (관목 20/50/250 m), 히스테리시스 3 m. 그림자 = 상세 LOD만(드리우기·받기).
6. **셰이딩**: 수피 = Standard. 잎·임포스터 = **Lambert + 태양 + 하늘 간접광만 켠 보조 AtmosphereLight**(`lightsNode` — 장면 밖, 다른 머티리얼은 환경맵) + 투과광 자체발광 22 %.
   Standard 잎은 겹쳐 그리는 알파 테스트에서 PMREM 표본 비용이 숲 시점 +3–4 ms, Lambert만으로는 그늘 잎·줄기가 새까맸다(골든 확인). 임포스터 = 틀(카메라 방향을 나무 로컬로 돌려 반팔면체 부호화) 선택 +
   구면 법선(아래 절반은 원기둥형).
7. **바람·계절**: 바람 = 높이² 비례 흔들림 + 잎 떨림(`time`, sim weather.windMs·windDirDeg). 계절 = dayOfYear 표(07 §8 — 은행 황엽 11/15–12/10, 벚꽃 3/25–4/8, 느티 갈색 11월, 낙엽수 겨울 가지만,
   상록 고정): 수종 슬롯별 잎 색·밀도 uniformArray, 잎은 조각 해시로 성기게.

## Consequences
- **MVP**(`20261001-3678f57-9c667fa9`): 나무 28,577(OSM 2,431·규칙 가로수 2,128·채우기 24,018, 셀당 최대 1,129, 절단 0), L0 합 185.8 MB(+1.2 MB).
- **나무 GPU**(실제 GPU, 1280×720 High·동적 해상도 끔, 수직 동기 해제 rAF 중앙값, 나무 켬 − `?trees=0`): **오모테산도 골든뷰 0.77 ms ✅**, 숲 상공(메이지 신궁, 고도 27 m) 2.96 ms,
  ⚠️ 숲 안(지면 11 m, 상세 LOD ≈ 70그루 + 그림자) 6.07 ms. 대안: 상세 LOD 잎 카드 감축·그림자 캐스케이드 0만, 임포스터 틀 반지름 수관 기준으로 조이기, GPU 컬링(M10 성능).
- 골든뷰 `omotesando-zelkova-autumn` 시점이 가로수길 밖(골목)이었다 → 가로수길 중앙 눈높이로 수정(views.json).
- ⚠️ PLATEAU veg 미사용(원천 없음), L1 HLOD 나무 임포스터 카드(04 §4.5)는 미구현 — L0 반경(384–768 m) 밖 공원은 HLOD 지면만. 규칙 가로수는 PLATEAU LOD1 도로 구역(보도 분류 없음)에선 생기지 않는다.
- 잎은 알파 테스트 계단(TAAU가 일부 완화). 야간 수목 조명은 M09.

# ADR-0072: 열차 — 메인 스레드 순수 함수 위치, 절차 가상 통근형 전동차(LOD 3 + 차내), 제3궤조
- Status: Accepted (M07-T03)
- Date: 2026-10-05

## Context
M07-T03 Do: s(trip, t) 순수 함수(가감속·제한속도), 편성 배치, 가상 통근형 전동차 모델(외관 LOD 3단 + 탑승 차량 내부), 노선색 띠, 팬터그래프.
Accept: 시각 점프 후 열차 위치가 연속 시뮬레이션 결과와 일치(±0.1 m), 역간 소요 시간이 시간표와 ±5 s. 10 §1은 열차를 sim.worker(30 Hz) → SAB로 그렸다.
T05(탑승·전면 전망)는 카메라가 열차에 붙는다 — 30 Hz 틱 + 외삽이면 곡선·정차 직전에 카메라가 cm 단위로 떤다(차량 외삽에서 실측한 종류). 사용자 요구: 실존 로고·정확한 도색 금지(노선색 띠만).
로드맵 Files의 `content/trains/emu-generic.blend`는 Blender 에셋을 가정했다.

## Decision
1. **위치 = 메인 스레드**: 열차 위치는 게임 시각의 순수 함수이고 싸다(운행 중 ≈ 10편성 × 11칸, 칸마다 이진 탐색 + 표본 보간 — 0.1 ms 미만).
   sim 시계 시스템(phase 10)이 시계 진행 직후 같은 프레임 시각으로 `rail/trains.ts`를 갱신 → `outputs().trains`(SharedInstanceBuffer 계약, 공유 메모리 아님 — 프레임마다 정확, 외삽 없음).
   render(70)·탑승 카메라(T05)·물리 목표(T04)가 같은 프레임 값을 본다. sim.worker는 열차를 모른다.
2. **운동**: 트립 곡선 = core `tripLegs`(시간표 컴파일러와 같은 입력 — ADR-0071) 트립별 캐시(운행 중일 때만). 정차 = 도착(곡선) ~ depS, 문 = 도착 +3 s 열기 시작·출발 −5 s 닫힘 끝(2.5 s 동작),
   쪽 = rail.bin 정차 side. 칸 자세 = 앞·뒤 대차(칸 길이 × 0.345) 선로 위치의 가운데·yaw·pitch(곡선에서 차체가 안쪽 — 실제와 같다). 터널 표본 칸 = 쓰지 않음.
3. **칸 버퍼(stride 8)**: x,y,z(레일 윗면, WF − anchor 256 m 격자)·yaw·pitch·속력·노선색 24비트 sRGB(정수 — float32 정확)·코드(정수 = 차형 × 4 + 종류, 소수 = (문 + 1)/2 × 0.999).
   종류 = 중간·팬터그래프(가공 전차선 노선 2·5·8…번째)·앞 운전실(전조등)·뒤 운전실(미등). 차형 = 20 m 통근형 4문(JR)·16 m 지하철형 3문(긴자선).
4. **모델 = 코드(Blender 에셋 대신)**: `render/trains/{parts,body,models,material,field}.ts` — 차량 조립기(`VehicleBuilder`) 재사용, 스테인리스 + 노선색 띠(인스턴스 색)만(로고·차번·정확한 도색 없음).
   LOD0(45 m) = 창 구멍 벽(얇은 상자 — 안팎) + 미닫이 문짝(셰이더 `_vpart.y` 방향 × 열림 × 0.62 m) + 차내(롱시트·칸막이 판·기둥·선반·실내등·문 위 안내 화면·운전실 칸막이·운전대) — 탑승·전면 전망용,
   LOD1(300 m) = 막힌 상자 + 어두운 유리 띠·대차, LOD2(1.6 km) = 상자. 싱글암 팬터그래프 접판 = 레일 위 5.2 m(셀 전차선과 같은 높이). 풀 24(차형 × 종류 × LOD), 머티리얼 1(`train`, MeshPhysical),
   `positionPrevious` = 속력 × 프레임 dt(TAA). 그림자 LOD 0–1. 정점 버퍼 7(≤ 8).
5. **제3궤조**: `RailLineMeta.thirdRail`(rail.bin 메타 JSON — 추가 필드, 형식 버전 그대로) — 긴자선은 가선·가선주 대신 바깥 제3궤조 메시, 팬터그래프 없음.
6. **적재**: game `world-rail.ts` — 첫 표시 뒤 `global/rail.bin`(DecompressionStream) + `global/timetables/index.json`·노선 파일(노선 사이 한 프레임 양보) → `sim.setRail` → `render.trains.bindShared`(장면 밖 선컴파일). `?trains=0` 끔. 골든뷰 안정 조건에 `trainsSettled`.

## Consequences
- 실데이터(T01 rail.bin + T02 시간표 1,758 트립): 곡선 도착 vs arrS 최대 0.043 s, 역간 소요 차 최대 0.05 s(±5 s ✅), 30 Hz 연속 vs 시각 점프 1,384 칸 표본 최대 0.0000 m(±0.1 m ✅ — 순수 함수).
- 적재 비용(실제 GPU): 시간표 JSON 파싱 1–2 ms/노선(텍스트 받은 뒤), 열차 선컴파일 0.5–0.9 s(장면 밖, 첫 표시 뒤).
- 메인 스레드 sim 비용이 생긴다(작다). 열차가 수백 편성으로 늘면(23구 확장) 워커 + 프레임 보간으로 옮기고 탑승 칸만 메인에서 다시 계산한다.
- 창 유리 없음(LOD0 구멍) — 근거리에서 반사가 없다. 문짝 창은 어두운 면. 차내 벽 안쪽 = 스테인리스 색(별도 내장 색 없음). 차내 안내 화면 글자 = T05.
- 터널 입구에서 칸이 통째로 사라진다(칸 중심이 터널 표본에 들어갈 때 — 긴자선 시부야 고가 끝).

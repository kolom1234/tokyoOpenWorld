# ADR-0101: 소크 테스트와 렌더 캐시 누수 — 메시 'dispose' 이벤트로 RenderObject 해제
- Status: Accepted (M11-T02)
- Date: 2026-10-19

## Context
- M11-T02: 1시간 자동 산책(도보 → 열차 → 차량 → 자유비행 반복), 힙·GPU 메모리 추세. 수락 = 10분 이후 증가 기울기 ≈ 0, 워커 재시작 0.

## Decision
1. **하네스** `pnpm soak`(tests/golden/soak.spec.ts — 실제 GPU Chrome, CI 제외, `?perf=1&audio=0`): [시부야 도보(달리기 4방향) → 하라주쿠 승강장 북행 열차 탑승·T 두 번(신주쿠 경계역 하차) → 주행 코스 운전 → 4곳 순환 상공 비행] 반복, 30 s마다 JS 힙·nvidia-smi 메모리·셀 수·모드, 콘솔 `restarted (#n)`·페이지 오류. 10분 이후 최소제곱 기울기. 열차 도우미는 `route-helpers.ts`(route.spec 공용).
2. **누수 수정**: 1차 소크 힙 +92 MB/분(1.5 → 6.7 GB). 힙 스냅샷 비교(순간이동 왕복 3회): Mesh +442·RenderObject +943·BufferAttribute +1,777·ArrayBuffer 데이터 +317 MB. three r186 RenderObject는 메시(Object3D)·머티리얼의 'dispose' 이벤트로만 RenderObjects 체인 맵에서 빠지고 geometry.dispose()는 속성 캐시만 비운다 → 공유 셀 머티리얼의 리스너가 해제한 메시를 붙잡았다. → `scene/release.ts releaseRenderObjects`(하위 트리에 'dispose' 이벤트)를 셀 해제·플레이어 탈것·승강장 메시 제거에 적용(render 모듈 카드 불변식).

## Consequences
- 2차 1시간 소크(2026-10-19, 13바퀴·열차 11회): JS 힙 기울기 **0.38 MB/분**(583 → 735 MB, 최대 1,042 MB — GC 전 값이라 오르내림), 워커 재시작 **0**, 오류 0 ✅. GPU 메모리(장치 전체) 기울기 2.46 MiB/분 — 30분 이후 +27 MiB(0.85 MiB/분)로 평탄해짐(파이프라인·텍스처 캐시가 차는 구간 추정) ⚠️ 관찰.
- 장면에서 영구히 빼는 새 메시 코드는 releaseRenderObjects를 거쳐야 한다(카드 불변식).

# ADR-0024: HLOD 파이프라인 (M02-T04)
- Status: Accepted
- Date: 2026-09-29

## Context
04 §4.5는 L1(L0 16개 병합·건물 simplify 25%·지형 4 m)·L2(LOD1 박스·지형 16 m)·L3(블록 매스·지형 64 m), 23구 LOD1 원경,
05 §4는 `hlod.mesh` = 자식 16영역별 프리미티브(`extras.child`)를 정했다. 정하지 않은 것: 원경 지형 소스(dem_1m.tif는 MVP 범위뿐),
23구 LOD1(2020, zip 5.3 GB·GML 17.3 GB)을 어떻게 읽을지, "LOD1 박스"·"블록 매스"의 구체 형태와 예산 맞추는 법, 영역 경계를 넘는 L1 셀의
영역 밖 자식, 레벨 간 건물 소속 일치, 레벨 경계 틈, 야간 발광 파라미터 표현, MVP 밖 구(區) 데이터.

## Decision
1. **자식 소속 = 중심점**: 모든 레벨에서 건물은 normalize와 같은 `centroidXZ`(면 외곽 링 정점 평균)가 든 자식 셀 그룹에 들어간다.
   L1 자식 그룹 i = L0 셀 i에 들어가는 바로 그 건물 → 자식 live 시 부모 그룹 숨김이 정확히 교체된다(L2/L3는 2020 원천이라 경계 근처 몇 동은 어긋날 수 있음).
   지형은 자식 정사각형마다 65² 격자 RTIN 패치(경계 정점 전부 유지) + **네 변 스커트**(깊이 = 격자 간격: 4/16/64 m)로 다른 레벨·원천 패치와의 T-접합 틈을 가린다.
   **05 §4의 "자식별 프리미티브(`extras.child`)" 대신 머티리얼별 프리미티브 1개 + 정점 속성 `_CHILD`(u8)**: 자식별 프리미티브는 셀당 최대 32 draw
   (07 §3 목표 L1 ≤ 8, L2/L3 ≤ 4)이고 메인 스레드에서 합치면 셀당 수 MB 복사가 생긴다. `_CHILD`면 셀당 draw 2개, 자식 표시·디더 페이드는
   렌더가 셀별 uniform(16개 값)으로 셰이더에서 고른다(M02-T05). 05 §4 갱신. 모든 프리미티브가 한 노드 변환(u16 균일 양자화)을 공유.
2. **L1**: 영역 안 자식 = L0 정규화 건물(LOD2/3 면) → 건물 단위 용접(1 cm, 건물 간 병합 금지) → `meshopt simplify`(목표 25%, 절대 오차 ≤ 2 m, `Prune`)
   → 평면 법선으로 풀기(UV 규칙은 L0와 같음), 지형 = dem_1m 4 m 표본(RTIN 0.25 m). 영역 밖 자식 = 23구 원경 박스 + 원경 DEM.
   L1 셀 = 영역 L0의 부모(MVP 24개). 예산(3 MB) 초과 시 비율 × 0.6ⁿ로 재시도(≤ 4회).
3. **원경 건물(FarBuilding)** = 23구 2020 zip을 **풀지 않고** `unzip -p` → SAX 리더 스트림(`readChunks`) → 건물마다 볼록 껍질의
   최소 면적 사각형(OBB)·최저 높이·높이(최고−최저)·바닥 면적·용도 → L2 셀 버킷 `data/derived/far-buildings/L2_*.ndjson.gz`. 워커 스레드 14개, 543 s(176.8만 동).
4. **L2** = OBB 박스(벽 4 + 지붕, 바닥 없음, 바닥은 2 m 묻음) — 높이 ≥ 20 m 또는 바닥 ≥ 1000 m² 중 부피 순 상한 12,000동, 나머지는 **64 m 격자 블록 매스**
   (칸 중심 정사각형, 한 변 = 64·√피복률 ≤ 0.9·64, 높이 = 면적 가중 평균, 피복 < 3%면 생략). 지형 16 m(RTIN 1 m).
   **L3** = 128 m 매스 + 높이 ≥ 80 m 개별 박스(스카이라인, 상한 4,000). 지형 64 m(RTIN 4 m). 예산(2 MB) 초과 시 박스 × 0.6ⁿ, 매스 격자 × 2.
   L2/L3 = `hlodExtentWF` 전체(12×12 = 144, 3×3 = 9 셀) — 23구 밖은 지형만.
5. **원경 지형** = 地理院 標高タイル `dem_png` z14(≈ 8 m 화소, 로그인 불필요)를 받아(`data/raw/gsi-dem-tiles`, 676 타일, manifest sha256 → lock `gsi-dem-tiles`)
   WF 8 m 격자로 재표본(투영은 256 m 거친 격자 보간, 화소 이중선형, 무효·해면 = 0 m). 기반지도정보 DEM(로그인 필요)을 48 km 범위로 받는 대신.
6. **야간 발광**: `_FACADE.flags`(HLOD 전용) = 하위 4비트 점등 단계(용도 코드: 상업 13·업무 10·주택 6–8·창고/공장 2, 미상 6) + 상위 4비트 창 패턴 시드
   (`hash32(WORLD_SEED, 'hlod-night', id)`). floors(= `_FACADE[1]`)와 함께 렌더가 창 발광 비율을 정한다(M03).
7. **MVP L0 원천**: 都 제공 pref 2025 판은 **3차 메시 단위**(이웃 구 zip의 같은 메시 = 같은 파일, CRC·크기 동일) → 시부야 zip + 신주쿠 zip의 4메시 + 메구로 zip의 1메시로 294셀 전체.
   normalize는 소스들을 한 번에 같은 버킷으로 처리하고 같은 파일명은 앞 소스만 읽는다(이전엔 소스마다 셀 파일을 덮어썼다).
8. 항공사진 저주파 지면색(04 §4.5 L2)은 머티리얼 시스템(M03)과 함께 — 이번엔 `_SURF` 기본값만.

## Consequences
- 수락: 크기 예산(L1 ≤ 3 MB, L2/L3 ≤ 2 MB)과 자식 그룹 합집합(모든 정점 `_CHILD` ∈ 0..15, 지형 자식 16개 = 부모 전체, stats.tris 일치)을 `validate`가 셀마다 검사.
  MVP 실빌드(20260928-7e215f4-7fb58d45): L1 24셀 평균 1.46 MiB·최대 2.42 MiB(L1_0_-4, 103k tris), L2 144셀 평균 378 KiB·최대 1.82 MiB(L2_2_-2),
  L3 9셀 평균 561 KiB·최대 1.39 MiB(L3_0_0) — 전부 예산 안(재시도 없음), validate 오류 0. hlod 73 s(컨테이너, 16코어 중 1스레드).
- 2020 원천(L2/L3)과 2025 원천(L0/L1)은 건물 목록이 다르다 → 원경 전환 시 신축·철거 건물이 나타나거나 사라질 수 있다(원거리라 수용).
- `hlod-prep`은 원천이 바뀔 때만(10분 내외), `hlod`는 빌드마다.

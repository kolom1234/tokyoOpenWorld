# ADR-0044: 계단·연석·에스컬레이터·지면 재질 — 엔진 먼저, 데이터는 M05-T01·교량 태스크 (M04-T04)
- Status: Accepted
- Date: 2026-09-30

## Context
M04-T04: 계단 램프 프록시(JCOL flags bit0) 생성, 연석 0.15 m 오르내림, 에스컬레이터 모드(0.5 m/s), `groundMaterial` 스냅샷. 수락 = 시부야역 주변 육교 계단 왕복 끊김 없음, 연석 카메라 튐 < 3 cm.
현재 파이프라인에는 **육교·계단 원천이 없다**: PLATEAU `brid` 리더 없음(04 §4.2 표에만), OSM `fetch` 미구현(sources.lock `osm-kanto` retrievedAt null), 역 오버라이드(M07) 없음.
**연석**은 보도 +0.15 m 지형 성형·도로 메시·연석 콜라이더와 한 몸(M05-T01 "Roads, sidewalks, curbs, terrain shaping") — 렌더 없이 충돌만 넣으면 보도에서 15 cm 떠 보인다.

## Decision
1. **엔진(이번 태스크)**
   - 워커 셀 콜라이더: JCOL 프리미티브(박스·캡슐·원기둥) 정적 바디 지원(연석·램프 프록시 박스·소품 대비). 바디 userData = 재질 | flags << 8 → `groundMaterial` = 하위 8비트.
   - 계단: 챌면 ≤ 0.40 m는 `ExtendedUpdate` 계단 오르기, 램프 프록시(bit0)는 일반 정적 충돌면(파이프라인이 계단 대신 경사면을 넣는다). 발 높이 변화 카메라는 **임계 감쇠 스프링**(ω 12/s — 0.15 m 연석의 최대 속도 ≈ 0.66 m/s = 60 fps 1.1 cm/프레임, 프레임률에 거의 무관).
   - **에스컬레이터 = JCOL SENSOR 박스 + flags bit2**(05 §6 확장, 포맷 v1 유지 — 옛 리더는 모르는 비트를 무시): 박스 로컬 +Z = 진행 방향(경사 포함). 바디 없이 OBB 목록 → 캐릭터 발(+0.1 m)이 안에 있으면
     진행 방향 × 0.5 m/s를 더하고 걷기 수평은 0.6 m/s로 제한(08 §5 "걸어서 오르기 +0.6"). 스냅샷 flags bit3 `BODY_ESCALATOR` → `Pose.escalator`(헤드밥 끔). 곡선 경로(스플라인)는 필요할 때 박스 여러 개로.
   - 지형 재질 = asphalt(1) 고정. `_SURF`(차도·보도·광장) 재질 격자는 M05-T01 지형 성형 때 물리 섹션과 함께.
   - `createInlineTransport()` 공개(같은 스레드 워커 코어) — Node 통합 테스트·도구용(브라우저 게임은 쓰지 않음).
2. **수락**: 합성 장면 자동 검사로 대신 — 실제 Jolt + traversal walk(연석 0.15 m·계단 0.18 m 카메라 프레임당 변화, 램프 프록시·에스컬레이터 속도·재질). 실제 육교 왕복은 ⚠️(데이터 없음).
3. **데이터 후속**: 연석·보도(M05-T01, 콜라이더 = 박스 프리미티브 체인), 육교·계단(교량 리더 `brid` + OSM `highway=steps` → 램프 프록시 bit0 — M05에 태스크 추가 제안), 역 에스컬레이터(M07 역 오버라이드 → bit2 박스).

## Consequences
- 게임 안에서 T04 기능이 보이는 곳은 아직 없다(건물 부속 계단은 0.3 m 단순화된 메시로 이미 오르내림). staging 보행은 T03과 동일.
- 05 §6 flags bit2 추가·08 §5 구현 메모. JCOL 버전은 그대로.

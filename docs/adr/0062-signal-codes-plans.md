# ADR-0062: 신호 = props.inst 신호 기둥의 현시 코드(교차로 ID·계획·그룹) + 게임 시각의 순수 함수 제어기 + 렌즈 발광
- Status: Accepted (M06-T02)
- Date: 2026-10-04

## Context
M06-T02 Do: 교차로별 현시, 보행 녹색 점멸, 스크램블 전방향 보행 현시, render 신호등 발광 연동. Accept: 스크램블 사이클이 계획표와 1 s 이내 일치(단위 테스트).
신호기는 M05-T03(ADR-0051)부터 파이프라인이 OSM `crossing=traffic_signals` 선에서 배치(`props.inst` 종류 3·4)했지만 어느 교차로·어느 방향인지 정보가 없었고,
05 §의 `meta.json signals` / `signalGroups`는 아직 없다. T05(교통)도 같은 그룹이 필요하다.

## Decision
1. **현시 코드**: 신호 기둥마다 `code = 교차로 ID(20비트) × 16 + 계획(2비트) × 4 + 그룹` — 2^24 미만이라 f32에 정확히 들어간다. `props.inst` **신호 종류(3·4)의 5번째 칸 = 코드**
   (원래 scale — 신호는 배율 1 고정이었다). 옛 빌드(코드 1) = ID 0·계획 0·그룹 1. 별도 섹션·meta 없이 셀 형식 그대로(추가 필드 없음, 05 §표에 명시).
   그룹: 0 차량 A, 1 차량 B, 2 보행 A(차량 A와 같이 녹색), 3 보행 B.
2. **교차로**(`tools/pipeline/src/stages/derive/props/signal-sites.ts`): PLATEAU 車道交差部(TrafficArea 1020) 조각(셀 + 8-이웃)을 1.5 m 안으로 붙은 것끼리 묶은 bbox 중심
   (스크램블은 1020 레코드 여러 개 → 합집합 찾기로 1개), ID = `hash32(round(cx), round(cz)) & 0xFFFFF`. 신호기 40 m 안에 교차로가 없으면 횡단 중점 4 m 격자(단일로 신호 횡단).
3. **그룹 = 가까운 도로 방향**: 교차로 중심 40 m 안 **OSM 차도 선**(셀 + 8-이웃, id 중복 제거 — 셀마다 같은 축)의 각도 5° 히스토그램 최고 봉우리 = A, A와 30° 이상 떨어진 최고 봉우리 = B
   (없으면 A + 90°). 차량 신호 = 진행 방향이 가까운 쪽, 보행 = 건너는 도로(보행 방향의 수직)가 B면 A. 신호기 방향과 같은 출처(OSM 선)라 어긋나지 않는다.
   거친 시도: PLATEAU 면 PCA·2배각 평균(직교 두 길이 지워져 축이 45°) → 4배각 십자 축 ±45°(비스듬한 교차로에서 같은 길 양쪽이 다른 그룹) → 셀 자기 OSM만(경계 교차로가 셀마다 다른 축).
   T05 차선 그래프 접근로도 같은 규칙(`nearerA`)으로 나눈다.
4. **계획**(`content/sim/signal-plans.json` — JSON, ADR-0061 §4): `plans[]`(이름·단계 {durS, groups[차량 A, 차량 B, 보행 A, 보행 B]}), 순서 = 코드의 계획 번호(추가만).
   기본 standard 120 s(A 녹 47 + 보행 점멸 5 + 황 3 + 전적 2, B 녹 53 + 5 + 3 + 2), scramble 120 s(A 38·B 38 차량 단계 + 전방향 보행 26 + 점멸 6 + 전적).
   `sites[]`(WF 중심·반경 → 계획) = 파이프라인이 코드에 굽는다(시부야 스크램블 중심 (−22.3, 8.6) 45 m).
5. **제어기**(`packages/sim/src/internal/signals/{plans,controller}.ts`): 상태 = **게임 시각의 순수 함수**(빨리감기·시각 점프 즉시 일관, 워커 왕복 없음 — 메인 `sim.signalStateAt(code)`).
   주기 오프셋 = 계획 0은 `hash32(WORLD_SEED, 'signal', ID) mod 주기`(이웃 교차로가 같은 박자로 바뀌지 않게), 사이트 계획은 0(한 사이트가 ID 여러 개여도 같은 박자).
6. **렌즈 발광**(render): 합친 소품 기하 `_ptype` = vec2(종류, 렌즈 표식 — 정점색으로 찾음: 차량 1 적·2 황·3 녹, 보행 4 적·5 녹), 인스턴스 `_itype` = vec2(종류, 램프 값 =
   차량 등 + 4 × 보행 등). 셰이더: 맞는 렌즈 = 정점색 × 6 발광(HDR), 아닌 렌즈 = 0.18 밝기. 보행 점멸 = 0.5 s 깜박(램프 값 계산에서). 배선 `render.setSignalLamps(lamp)`가
   보이는 기둥 슬롯만 매 renderPrep에 묻고 바뀐 범위만 올린다. **WebGPU 정점 버퍼 상한 8**: 속성을 따로 두면(`_lamp`·`_isig`) 9–10개 → 실 GPU 파이프라인 생성 실패로
   소품 전체가 사라졌다(SwiftShader WebGL2는 통과) → vec2로 합치고 단위 테스트(기하 속성 + 3 ≤ 8)로 막는다.

## Consequences
- 실 GPU(RTX 3050 Laptop, WebGPU) 스크램블: 북향 차량 등 10 s 녹·60 s 적·95 s 적, 서향 10 s 적·60 s 녹·95 s 적, 보행 등 95 s 전방향 녹(`docs/screenshots/M06/T02/`).
- 9셀 부분 빌드 통계: 교차로 12, 같은 그룹 쌍 65 중 진행 방향 45° 넘게 다른 것 3, 다른 그룹 쌍 63 중 45° 안 3 — 모두 5갈래 교차로(도겐자카 쪽 대각 세 번째 길)의 기둥 1개.
  ⚠️ 4갈래 넘는 교차로의 세 번째 방향은 가까운 그룹에 붙는다(2현시 모델 한계). 대안 = 계획에 그룹 추가(코드 그룹 2비트 — 차량 C·D는 계획 번호 비트를 늘리는 형식 변경 필요).
- 셀 형식·스키마 변경 없음(5번째 칸 의미만). 신호 소품이 있는 셀은 재빌드해야 코드가 생긴다(옛 빌드 = 모든 신호 같은 박자의 기본 계획).
- 교차로 ID는 1020 묶음 bbox 중심 반올림 해시 — PLATEAU 갱신으로 면이 바뀌면 오프셋(박자)이 바뀐다(결정론은 같은 입력 기준).

# ADR-0066: 교통 외형·키네마틱 동기 — 가상 절차 차종 7종·TAA 모션 벡터·sim→physics 직결 상자·횡단보도 정차 금지
- Status: Accepted (M06-T06)
- Date: 2026-10-05

## Context
M06-T06 Do: 가상 디자인 차종 7종(LOD 3단 + 바퀴 회전 셰이더 + 등화), 플레이어 60 m 내 키네마틱 바디 동기화(sim→physics MessageChannel). Accept: 도보 중 차량과 겹침(관통) 0.
사용자 규칙: 외형 완전 가상(실존 로고·브랜드·번호판 없음), 차량 모델 = 자체 제작 또는 CC0/MIT(출처 기록). 08 §8은 열차용 sim→physics 직결(MoveKinematic)을 이미 정해 두었다.
실제 GPU 첫 확인에서 두 문제가 드러났다: (1) 차량·군중 모서리 계단·반짝임 — three r186 `VelocityNode`의 이전 위치 = `positionPrevious`(기본 = 변환 전 `positionGeometry`)라
positionNode로 인스턴스를 놓는 머티리얼은 모션 벡터가 틀려 TAA가 매 프레임 히스토리를 버린다. (2) 신호 대기 차가 횡단보도 위에 선다 — T05 정지선 = 교차점 후퇴(반폭 + 6 m)라 넓은 횡단보도(스크램블 8.5–9 m)를 넘지 못한다.
또 차가 노면 위로 −0.40…+0.71 m 뜨고 묻혔다(차선 점 간격이 길어 지형 굴곡을 못 따라감).

## Decision
1. **공유 계약(core)**: `VEHICLE_TYPES`(VehicleTypeInfo name·길이·폭·높이·비율 — 세단 4.6·택시 4.7·경 왜건 3.4·경트럭 3.4·미니밴 4.7·택배 트럭 6.6·버스 10.5 m, 순서 = variant 하위 3비트)를 sim 스폰·render 모델·physics 상자가 같이 쓴다.
   `KinematicFrame { t: 'kin', atMs, data: Float64Array }`(`KINEMATIC_STRIDE` 9 = id, WF 바닥 중심 x,y,z, yaw, 속력, 길이, 폭, 높이) — sim·physics가 서로 모르는 채 포트로 주고받는 형식(01 §4 레이어 유지).
2. **render `vehicles/*`**: 자체 절차 모델(육면체·사다리꼴·바퀴 원기둥 + 휠 살, 부품 코드 `_vpart` = 고정·도장·유리·바퀴·전조등·후미등·좌우 깜빡이·택시 지붕등·액센트), LOD 35/110/520 m(LOD0 = 휠 살·거울·B 기둥·범퍼, LOD2 = 6각 바퀴),
   (차종 × LOD) 풀 21개·머티리얼 1개(MeshPhysicalNodeMaterial — 도장·액센트 = 인스턴스 sRGB 24비트 + 클리어코트, 유리 = 어두운 + 클리어코트), 바퀴 = 축 둘레 회전(sim 회전 수 + 외삽),
   등화 = 전조등(밤 = 태양 고도 smoothstep(+4.6° → −2.9°) × 5 + 낮 주간등 0.15)·후미등(밤 1.2 + 제동 flag 4)·깜빡이 1.5 Hz(flags bit1·2)·택시 지붕등. 도장 팔레트 32(흰·은·검 위주)·택시 6색·버스 차체 3 × 줄무늬 4·화물 상자 5 — 모두 가상, 글자·엠블럼·번호판 없음.
   처음 `vehicles.bindShared` 때 풀 생성 → `compileAsync`(보이지 않는 인스턴스) → 그리기. 그림자 = LOD 0–1. 정점 버퍼 7(≤ 8 단위 테스트).
3. **모션 벡터**: positionNode 안에서 `positionPrevious.assign(같은 변환(지난 프레임 위치))` — 차량 = `_imove`(지난 프레임 변위·바퀴 회전), 군중 = `_ivar.zw`(빈 칸에 프레임 변위 x·z).
   나무·간판·원경 스프라이트도 같은 문제(별도 작업으로 넘김).
4. **physics `worker/kinematics.ts`** + `connectKinematicSource(port)`: 포트 프레임은 받아 두기만 하고 step 안에서 반영(생성·치수 바뀌면 재생성·빠진 차 제거, 0.5 s 조용하면 전부 제거),
   상자 = 폭 × (높이 − 바닥 틈 0.15 m) × 길이(NPC_KINEMATIC), 스텝마다 목표 = 포즈 + 전방 × 속력 × min(받은 뒤 경과 + 전송 지연, 0.25 s) → `MoveKinematic`, 순서 = MoveKinematic → 캐릭터 ExtendedUpdate → 월드 스텝
   (CharacterVirtual이 접촉 속도로 밀린다). 앵커 재설정 = −Δ. 스냅샷 메타 10칸(8 = 키네마틱 바디 수, 9 = 받은 프레임 수).
5. **sim**: `SimService.connectPhysics(link)` — 워커 (재)시작마다 MessageChannel(port1 → 워커, port2 → link → physics). 워커는 교통 틱 뒤 플레이어 60 m 안 차량 프레임을 보낸다(비면 직전이 비지 않았을 때만).
   교통 출력 차체 중심 = 앞 − 길이/2를 지나온 차선(trail ≤ 4)까지 거슬러(차선 넘김 때 중심이 새 차선 시작에 고정돼 최대 길이/2 튀던 것 — 걷기 봇 0.62 m 관통의 원인).
6. **횡단보도 위 정차 금지(런타임)**: 서야 할 때(신호·출구 막힘·양보) 정지 지점 앞 35 m 안에서 경로가 횡단 띠(nav.bin 횡단 기록 — 군중 내비 월드 `crossingsNear`)에 들면 띠 앞 1 m에서 선다.
   차 앞이 이미 든 띠는 무시하고, 황색에 이미 띠 안이면 통과. 경로 미리보기 = 다음·그다음 + 후속이 하나뿐인 조각(셀 경계 포털·연결로) 80 m.
   — 파이프라인에서 차선 끝을 횡단 띠 앞으로 자르는 안을 먼저 시도했으나 스크램블처럼 OSM 교차점이 짧은 간선(1–26 m)으로 쪼개진 곳에서 차선이 1 m로 무너지고 신호가 빠졌다(되돌림).
7. **파이프라인**: 차선 점 간격 ≤ 4 m(점마다 지면 높이) — 차 높이 오차 −0.40…+0.71 → ±0.02 m. lanes.bin 형식은 같다(점만 늘어남).
8. game: `startCrowdLater`가 `sim.outputs().traffic` → `render.vehicles.bindShared`, `sim.connectPhysics(port → physics.connectKinematicSource)`. `?traffic=0` = 교통 없음(비용 비교).

## Consequences
- 단위: 물리(실제 Jolt) 8 m/s 차가 선 캐릭터를 밀어냄 — 같은 시각 침투 0(최소 간격 0.136 m), 정지 차에 걸어 들어가면 0.020 m(패딩)에서 멈춤. sim world-mini: 출력 중심 틱당 튐 < 0.3 m,
  적·황 대기 중 횡단보도 위 정차 2310/6524 → 0/5078(녹색 출구 막힘으로 띠 안에 남는 경우 0.3 %는 기록만), 교착·위반 0, 메이지도리 비율 0.36(⚠️ T05와 같음). render: 치수·감기·LOD·정점 버퍼.
- **실제 GPU(RTX 3050 Laptop, Chrome WebGPU, 로컬 9셀 정오 차 90 + 보행자 950)**:
  - **걷기 봇 5분 × 2**(WASD 8방향, 절반은 가까운 움직이는 차 쪽으로 — 차도 횡단 유도, 매 프레임 같은 시각 캡슐 vs 차체): seed 3 = 669 m·차 1.5 m 안 745프레임, seed 11 = 637 m·1,925프레임 —
    **관통(> 5 cm) 0 ✅·낙하 0·끼임 0**, 최대 침투 0.021·0.002 m(캐릭터 패딩 안). 중심 연속 수정 전 1회차는 정지 차 0.62 m 관통 2프레임(차선 넘김 튐) → 수정 뒤 0.
  - 물리 틱 0.12–0.33 ms(≤ 4 ✅, 키네마틱 바디 최대 19), sim 틱 p95 2.7–4.5 ms(시작 직후 6.7–8.3, ≤ 12 ✅), 60 FPS(수직 동기).
  - GPU 비용(2560×1440 High, 수직 동기 해제, 같은 포즈 교통 켬 − `traffic=0`, 전력 상한 32–34 W·소비 21–23 W): 거리(차 18–25대 보임, LOD0–2) p50 +1.30 / −0.35 ms(정지 화면에서 동적 캐스터가
    그림자를 "움직일 때" 일정으로 — ADR-0039), 상공(37대 LOD2) +0.01 ms. 소비 22.6 → 29.1 W로 흔들린 상공 1회차는 버림. 차 모델 102–432 삼각형.
  - 늦은 적재 구간 프레임 멈춤(첫 표시 뒤 25 s, rAF > 50 ms): 교통 켬 0.68·0.87·0.27 s, 끔 0.57·1.0·0.33·0.08 s — 차량 compileAsync(2.5–4.4 s)가 새 멈춤을 만들지 않음(군중·간판·나무 적재 멈춤은 기존).
- 스크린샷 `docs/screenshots/M06/T06/`: 정오 7종(`vehicles-noon.jpg`), 야간 등화(`vehicles-night-lights.jpg` — 도시 야간 조명은 M09), 횡단보도 앞 대기(`taxi-waits-before-crosswalk.jpg`), 수정 전(횡단보도 위·계단 현상).
- 차량은 기울지 않는다(yaw만) — 언덕(도겐자카 ≈ 5 %)에서 차 끝이 ±0.1 m. 차 사이 물리 충돌·차와 군중 물리 충돌은 없다(레이어 행렬). 물리 워커가 재시작되면 직결 포트가 끊긴다(sim 재시작은 다시 연결).

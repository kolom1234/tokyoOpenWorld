# ADR-0100: 성능 패스 — `pnpm perf` 하네스, 정적 행렬 갱신 제외, 첫 표시 = 셰이더 컴파일(LUT 굽기 기각)
- Status: Accepted (M11-T01)
- Date: 2026-10-19

## Context
- M11-T01: 비행 경로 3종 측정 → 예산 초과 항목별 해결, 수락 = 14 §2 전 항목(High, 기준 GPU 2종). 측정 하네스(`pnpm perf`·perf-latest.md)가 없었다.
- 기준 GPU는 이 PC 한 대(RTX 3050 4GB Laptop, 전력 상한 ≈ 34 W) — 14 §2 기준(RTX 3060급 / M1 Pro급 2종)과 다르다(사용자 결정: 이 PC 기준, "2종"은 ⚠️).
- 사용자 요청: 첫 표시 편차(대기 셰이더 선컴파일 4.9–6.4 s)를 빌드 시 LUT 굽기 등으로 해결.

## Decision
1. **하네스** `pnpm perf`(tests/golden/perf.spec.ts — 실제 GPU Chrome, CI 제외): 2560×1440 High·동적 해상도 끔·vsync·프레임 상한 해제(rAF 간격 = 실제 프레임 비용). 경로 ① 스크램블 도보(달리기 4방향) ② 시부야 시가지 자동 주행(스크램블 출발 차선, 교통·군중 켬 — 14 §2의 "메이지도리"는 차선 자동 주행 출발점 때문에 대체) ③ 신주쿠 상공 자유비행 + 포토 DOF 전환 + 부팅(새 컨텍스트). 지표 = 프레임 p50/p90/p95/p99, rAF 콜백 합(메인 작업)·스케줄러 시스템별 시간(core `Scheduler.timings` 신설), 물리·sim 틱, JS 힙, nvidia-smi 전력·메모리, 드로우콜·삼각형, GPU 패스 비중(`PERF_GPU_TIMING=1`), 스트리밍 정지. 결과 perf-results/<날짜>.json + docs/generated/perf-latest.md. `?perf=1` = 측정 핸들만(오버레이·stats-gl·debug 로그 없이 — `?debug=1`은 콘솔 로그 비용으로 측정을 부풀렸다). 환경 변수 PERF_VIEWPORT·PERF_QUALITY·PERF_SECONDS·PERF_GPU_TIMING.
2. **CPU**: 스케줄러 시간 = render 시스템이 거의 전부(다른 시스템 합 ≈ 1.5 ms). 프로파일(CDP): 야간 광원 풀(PointLight 1024개 — 낮에도)과 셀 그룹 행렬 갱신이 매 프레임·매 그림자 패스. → 광원 풀 `matrixWorldAutoUpdate = false`(재배정 때만 갱신), 셀 슬롯 그룹은 `matrixAutoUpdate = false`(배치·원점 재설정 때만 로컬 행렬). **정정**: 셀 그룹까지 `matrixWorldAutoUpdate = false`로 하자 일부 셀 월드 행렬이 늦게 맞아 덜 그려졌고(삼각형 7.0 → 5.0 M — "도보 p50 19 → 15 ms"는 이 착시), CI 정지 떨림 e2e가 0.43 %로 실패했다 → 셀 그룹은 월드 순회 유지.
3. **첫 표시**: 단계 계측(대기 준비 = 장면 compileAsync·첫 렌더·LUT) 결과 **LUT 계산은 65–420 ms**, 시간은 셰이더 컴파일(셀 머티리얼 5종 + 프리패스 ≈ 4.6 s, 대기·조명 ≈ 0.4 s — 동시에 걸면 서로 막아 "대기"로 보였다). → **LUT 굽기 기각**(줄일 것이 거의 없다). 동시/순서 실행 A/B(번갈아 3회)는 차이 없음(6.89 vs 6.78 s 평균, 잡음 ±0.5 s) → 그대로. 편차의 원인 = D3D 셰이더 컴파일 CPU 시간의 전력·발열 의존. 재방문은 브라우저 셰이더 캐시로 3.2–4.0 s(첫 방문 6.0–7.7 s, 로컬 dev). 공개(메뉴 모드)는 타이틀 화면 뒤에서 컴파일한다.
4. **포토 DOF**: 출력 노드 교체(M10 잔여) — 전에는 켜고 끌 **때마다** 후처리 전체 재구성(4.8 s), 지금은 첫 켜기만 2.0–4.6 s(전력·발열 상태), 이후 전환 0.26–0.65 s. 포토 모드 진입 때 compileAsync로 미리 만드는 시도는 진입에 1.95 s 멈춤이 새로 생기고(동기 셰이더 생성) 합계 이득이 없어 기각.
5. **렌더 번들(BundleGroup)**: 녹화 시점 카메라로만 컬링돼(컬링 끄면 정점 부하 증가) 기각 — 후속(셀 드로우콜 병합) 과제.

## Consequences (2026-10-19, 이 PC, 1440p High — 같은 코드도 전력 상한 28.6–35 W·발열에 따라 프레임 ±25 % 흔들린다)
- ✅ 물리 틱 최대 0.6–3.4 ms, JS 힙 ≤ 741 MB, GPU 메모리 증가 ≤ 211 MB, 스트리밍 정지 0, 첫 표시 ≈ 10 s(로컬 dev — 번들 안 된 모듈).
- ⚠️ 프레임 p50 도보 19–24·주행 25·비행 15–16 ms, p95 30–46 ms: GPU 한계(전력 상한 근처, 패스 비중 장면 44 %·SSR 12 %·AO 10 %·그림자 8 %). 주행은 교통·군중으로 드로우콜 617·삼각형 1,317만. 기준 GPU(데스크톱 3060급)는 미측정.
- ⚠️ 메인 스레드/프레임 p95 17–39 ms: render 시스템(three.js WebGPU 드로우콜당 CPU — 유니폼 쓰기·바인딩·그림자 캐스케이드 + GPU 역압 대기). 다른 시스템 합 ≈ 1.5 ms. 대안: 셀 슬롯 병합(드로우콜 ↓)·그림자 캐스터 축소·Medium 기본.
- ⚠️ sim 틱 p95 12.8 ms(스크램블 군중, 측정마다 7.6–15 ms — 메인과 CPU 경합).
- ⚠️ 초기 다운로드 124 MB는 로컬 dev(번들 안 된 JS) 값 — 예산 판정은 staging `GOLDEN_BOOT=1`(PROGRESS 기록).

# ADR-0021: 스트리밍 관심 영역·우선순위 수치 확정 (M02-T01)
- Status: Accepted
- Date: 2026-09-28

## Context
M02-T01에서 06 §3–4를 순수 함수(`packages/streaming/src/internal/{cell-index,interest,priority,geometry}.ts`)로 구현했다.
구현 중 문서 규칙에 수치가 없거나(고고도 L1 확장, 열차 진행 방향 가중, 고도 전환) 식이 서로 모순되는 곳(우선순위의 발밑 배율·부모 항)이 드러났다.

## Decision
1. **고고도 L1 확장** = `R1 = 3000 + 1.0 × (고도 − 300)` m, 상한 **3.5 km**(고도 800 m에서 도달). 해제 반경 4.375 km 안 셀 수가
   최대 80(셀 내 위치 32×32 샘플)이라 **L1 상주 한도 64 → 80**(한도 ≥ 해제 반경 셀 수 원칙 유지). 메모리 영향(+16셀)은 HLOD 크기가 정해지는 M02-T04에서 확인한다.
2. **고도 전환 히스테리시스**(상태 없이 같은 × 1.25 비율): 고도 ≤ 300 m 원형 R0 / 300–375 m 로드 3×3·유지 원형 `R0 × 1.25` /
   375 m 초과 로드 3×3·유지 5×5. 300 m 부근을 오르내려도 링 셀이 반복 해제·재요청되지 않는다(스래싱 대역 90 m).
3. **고도 = 지면 기준**(`posWF.y − groundHeightAt`, 모르면 지면 0 m → T.P. 그대로. 도쿄 지면 T.P. 0–40 m라 오차 ≤ 40 m).
   고고도 규칙은 모든 모드에 적용(초고층 전망대 도보도 포함) — freecam 고도항(`+ 0.5 × 고도`)만 freecam 전용.
4. **열차 진행 방향 가중** = L0만, 수평 속도 > 5 m/s일 때 거리 × `(1 + 0.5 × max(0, −cosθ))`. 뒤쪽 유효 반경 ≈ 512 m.
   실측: 정지 42 / 진행 35셀(+ lookahead 90 m 합집합 33–41 / 해제 47–58) → 72 이내. L1·L2에는 적용 안 함(문서가 R0에만 붙임).
5. **우선순위 식 정정**:
   - 발밑 셀 `× 0.01` → **고정 점수 −1**. 발밑 셀은 d = 0이라 배율이 무의미했고(다른 d = 0 셀과 동률), 부모 항 −0.5가 붙은 다른 셀이 더 앞설 수 있었다.
     발밑 = `player`·`teleport` 관심점이 든 L0 셀(순간이동 도착지도 물리 필수).
   - `parentNotLive ? −0.5` → **부모 선행 클램프** `score(child) = max(score, score(parent) + 0.001)`(부모가 같은 요청 후보일 때, 상위 레벨부터).
     자식에게 −0.5를 주면 자식이 부모보다 **앞서** 요청돼 "부모 먼저" 의도와 반대였다. 발밑 셀은 면제(물리 > 시각).
     부모가 이미 요청·live·failed면 제약 없음(failed 부모가 자식을 막지 않음).
   - teleport 배율·`weight`는 관심점별 거리에 적용 후 최소(`min_i d_i / w_i × tf_i`), `weight ≤ 0` 관심점은 우선순위에서 제외(집합 계산에는 포함).
   - `inFrustum` → **카메라 forward 기준 수평 ±60° 쐐기**와 셀 AABB 교차(streaming은 카메라 절두체를 모른다). 동률은 셀 키 오름차순.
6. `transition` 모드 R0 = 384 m(도보). 도착지 로딩은 `whenReady`가 보장한다(06 §8).
7. 모드·품질 티어는 `InterestPoint`에 넣지 않고 streaming이 `mode/changed`·`quality/changed`로 추적해 `InterestFrame`에 넣는다(core 타입 불변).

## Consequences
- 부팅·순간이동 요청 순서 = 발밑 셀 → L3 → L2 → L1 → 나머지 거리순(06 §8 순서와 일치, 발밑 셀만 앞당김).
- 수치는 `StreamingConfig`(`packages/streaming/src/api.ts`, 기본값 `internal/config.ts`)로 조정 가능. 바꾸면 `test/interest.test.ts` 셀 수 표와 06 §3 표를 같이 갱신.
- "3초 내 도착 불가 → 한 레벨 위 HLOD 먼저"(06 §4)는 대역폭 EMA가 필요해 스케줄러(M02-T02/T03)에서 `CellIndex.byteLength`로 구현.

## Alternatives
- 문서 식 그대로(× 0.01, −0.5): 위 모순 때문에 "발밑 셀 최우선"·"부모 선행" 테스트를 동시에 만족할 수 없음 → 기각.
- 고고도 L1 확장 없음(R1 = 3 km 고정): 경사 거리 기준으로는 충분하지만 06 §3이 확장을 요구하고, 3×3 밖 L0 링이 L1로 바뀌는 경계가 위에서 잘 보임 → 소폭(≤ 3.5 km) 확장.
- 고도 전환에 상태(이전 고고도 여부) 보관: 관심점에 식별자가 없어 추적 불가 → 비율 기반 무상태 히스테리시스.

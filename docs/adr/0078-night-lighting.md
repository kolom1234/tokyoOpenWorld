# ADR-0078: 야간 조명 = 규칙 배치 lights.bin + ClusteredLighting 고정 풀 1024 + 발광 스프라이트 + 창 점등 스케줄(L0·HLOD·랜드마크), LightProbeGrid 불채택
- Status: Accepted (M09-T03)
- Date: 2026-10-11

## Context
M09-T03 Do: lights.bin 생성, ClusteredLightsNode 등록·거리 컬링, 창 점등 스케줄, 간판 점등, 원거리 발광 스프라이트, HLOD 야경 마스크, LightProbeGrid 채택 여부(ADR).
Accept: 21:00 스크램블 골든뷰, 광원 처리 ≤ 2 ms(High, 1024개). 실측 조명 데이터(가로등 위치·광속)는 없다.

## Decision
1. **lights.bin(셀 L0, 05 §4)** — 파이프라인 `build/lights-cell.ts` 규칙 배치(가상): 가로등 머리(소품 streetLamp, 4000 K·4000 lm·20 m), 자판기 앞면(6000 K·300 lm·상시),
   돌출·입간판(3500–6500 K, 간판 일정), retail 파사드 건물 1층 벽 앞 7 m 간격(3000–5000 K·900 lm, 영업 일정). 셀당 ≤ 600(넘으면 상점 앞부터 뺀다). 결정론 = gmlId·위치 해시.
2. **실제 광원**(render `lighting/night-lights.ts`): three `ClusteredLighting(1024)`(WebGPU만, 컴퓨트 클러스터링). 풀 PointLight 1024개를 **부팅 때 고정**(조명 목록이 바뀌면 모든 머티리얼이 재컴파일된다) —
   0.25 s마다(또는 20 m 이동·원점 재설정) 카메라 300 m 안 켜진 광원 중 가까운 순으로 배정, 남는 슬롯은 세기 0·지하 1e5 m. 티어별 켜는 수 Low 64·Medium 256·High/Ultra 1024.
   켜짐 = 일정 비율(schedule.ts — 해 진 뒤·영업·간판 시각) > 광원 해시. 세기 = lm/4π × `LIGHT_SCENE_K`(0.12, 실제 GPU 조정) × 종류 배율.
   **종류별 감쇠**: 가로등·자판기 = 역제곱, 상점 앞·간판 = 1차(벽 0.6 m 앞 점광원의 역제곱은 벽에 흰 얼룩을 만든다 — 실제는 처마 다운라이트·쇼윈도 면광원) + 배율 0.25·0.2.
3. **발광 스프라이트**: 1.5 km 안 켜진 가로등·자판기만 가산 사변형(최대 6000, 120 m부터 거리 비례 확대) + 블룸. 상점 앞·간판 광원은 빛 번짐 자리라 스프라이트 없음.
4. **창 점등 스케줄**(07 §5-5): 클래스(사무·맨션·주택·상업·공공·공업) × JST 시 × 요일 유형(평일·토·휴일, core `EnvironmentState.dayType`) 비율표, 창 시드 해시 < 비율이면 켜짐(내려갈 때 같은 순서로 꺼진다).
   L0 파사드 = 실내 매핑 발광 × 3.2(켜짐)·0.06(꺼짐), **HLOD** = `_FACADE.flags`(점등 단계·창 시드) + 벽 UV 3.4 × 2.6 m 격자 발광(0.05), **랜드마크** = 커튼월·핀·화강암 창 칸 발광(0.05, 사무 비율).
   칸이 1화소보다 작아지면(fwidth) 칸 판정 대신 기대값(비율 × 면적)으로 섞어 원경 반짝임을 없앤다.
5. **밤 산란광**: 반구 조명(하늘 보라·땅 주황) 0.015 × 밤 정도 — 광원이 닿지 않는 노면·벽이 어렴풋이 보이게. 카메라 T.P. 90–260 m에서 0으로 페이드
   (상공에서는 밝은 단색 HLOD 상자가 전부 회색으로 떠올랐다 — 창 불빛만 남긴다). 맑은 밤 하늘 = 지평선 주황 광해(장면 평균 휘도 × 0.9, `post/weather-sky.ts`).
   나무 잎의 투과광 자체발광(0.22)은 밤 정도로 줄이고(밤 가로수가 연두색으로 빛났다), 잎 전용 조명 목록에 산란광을 넣는다(클러스터 가로등은 잎에 닿지 않는다 — 한계).
6. **LightProbeGrid 불채택**: three `LightProbeGrid`는 탐침마다 큐브 렌더 → SH 굽기다. 시각·날씨·스트리밍(셀 적재·원점 재설정)마다 다시 구워야 하고 그 비용이 메인 스레드 예산(호출 4 ms·프레임 6 ms)과 GPU 예산을 넘는다.
   파이프라인 정적 굽기는 하늘·태양에 따라 바뀌는 간접광과 맞지 않는다. 낮 간접광 = SSGI(High+)·GTAO + 하늘 환경 프로브, 밤 = 위 산란광으로 충분하다고 판단(재평가: 실내·지하 공간이 생기는 M10 이후).
7. 소프트웨어 래스터(CI)·WebGL2 = 클러스터 없음(스프라이트·발광만). 비용 A/B: `?nightLights=0`(클러스터 끔), `debugLayerVisible('nightLights', false)`(켠 수 0).

## Consequences
- 수락 측정(실제 GPU, 2560×1440 High, 수직 동기 해제 rAF p50, GPU W): PR 본문·PROGRESS.
- 한계: 광원 위치는 규칙(가상) — 실제 가로등 배치와 다르다. 광원 그림자 없음. HLOD 창은 층 높이 고정 격자(건물 실제 층과 어긋날 수 있음). 나무 잎은 가로등을 받지 않는다.
  야간 간판 글자·영상 화면 밝기는 낮과 같은 발광(노출이 밤에 올라가 더 밝아 보인다).
